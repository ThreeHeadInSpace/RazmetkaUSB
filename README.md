# Кнопка автоматической разметки JACP

**Текущая версия: v8.5**

Bookmarklet предназначен для ускорения проверки диалогов бота в JCP.

После запуска скрипт автоматически определяет сообщения, которые требуют проверки, ставит им метку **«Верно»** и визуально выделяет их оранжевым цветом.

Сообщения, которые по известным правилам не требуют разметки, автоматически пропускаются.

---

## Общий принцип

Логика работает по принципу:

> По умолчанию сообщение нужно разметить.
> Оно пропускается только в том случае, если сработало одно из явно заданных безопасных исключений.

Для каждого сообщения скрипт анализирует:

* Class;
* State;
* текст сообщения клиента;
* текст ответа бота;
* кнопки быстрого ответа из предыдущего сообщения;
* специальные текстовые шаблоны.

После этого определяется `skipReason`.

Если `skipReason = null`, сообщение размечается как **«Верно»**.

Если найдена причина пропуска, сообщение остаётся без изменений.

---

# Порядок работы

## 1. Подготовка диалога

При запуске bookmarklet:

1. находится метка проверяющего `.Ведерников И. Ю.`;
2. нажимается верхняя метка **«Верно»**;
3. находятся все элементы `div.Message_container`;
4. каждое сообщение отдельно анализируется по правилам ниже.

Если одна из кнопок верхней панели не найдена, скрипт продолжает работу.

---

# Приоритетные правила

## 2. NoMatch

Если `nomatch` встречается в **Class или State**, сообщение всегда оставляется для проверки.

Другие правила пропуска в этом случае не применяются.

То есть:

```text
NoMatch -> размечаем "Верно"
```

`NoMatch` имеет самый высокий приоритет.

---

## 3. TransferToOperator

Если `transfertooperator` встречается в Class или State, включается специальная логика.

Пропускается только известная безопасная комбинация:

```text
Class содержит:
generalstates/clarity

И одновременно State содержит:
generalstates/transfertooperator
```

Для неё:

```text
Clarity + TransferToOperator -> пропустить
```

Любой другой `TransferToOperator` остаётся для проверки и размечается.

Важно: после обнаружения `TransferToOperator` обычные текстовые исключения ниже уже не проверяются.

То есть приветствие, благодарность, quick reply, запрос оператора и техническая ошибка не отменяют проверку неизвестного `TransferToOperator`.

---

# Исключения по Class и State

## 4. Безопасные Class

Сообщение пропускается, если Class содержит:

```text
selling
/handlers/timeouthandler
```

---

## 5. Безопасные State

Сообщение пропускается, если State содержит:

```text
anyerror
fileevent
timeouthandler
limithandler
```

---

## 6. Безопасные пары Class + State

Некоторые значения безопасны только вместе.

Сейчас используется пара:

```text
Class: generalstates/clarity
State: generalstates/transfertooperator
```

Такие сочетания хранятся отдельно в:

```text
SKIP_CLASS_STATE_PAIRS
```

---

# Текстовые исключения

## 7. Нажатие кнопки быстрого ответа

Если текст текущего сообщения клиента полностью совпадает с одной из кнопок, показанных ботом в предыдущем сообщении, считается, что клиент просто нажал quick reply.

Например:

```text
Бот:
[Да] [Нет]

Клиент:
Да
```

Такое сообщение пропускается.

Диагностическая причина:

```text
buttonClick
```

---

## 8. Чистые приветствия

Сообщение пропускается, если оно целиком является приветствием.

Поддерживаются, например:

```text
Добрый день
Доброго дня
День добрый
Добрый вечер
Доброго вечера
Доброе утро
Доброго утра
Доброй ночи
Здравствуйте
Здравствуй
Привет
Приветствую
Доброго времени суток
```

Пунктуация по краям сообщения не мешает определению приветствия.

Например:

```text
Здравствуйте!
```

будет пропущено.

Но:

```text
Здравствуйте, где моя карта?
```

уже содержит полезный вопрос и должно быть размечено.

Диагностическая причина:

```text
greeting
```

---

## 9. Чистые прощания

Скрипт распознаёт короткие сообщения вроде:

```text
Пока
До свидания
Досвидания
Досвидос
Всего доброго
Всего хорошего
Всего вам доброго
Хорошего дня
Хорошего вечера
До встречи
Прощай
Прощайте
```

Диагностическая причина:

```text
goodbye
```

### Важный нюанс текущей v8.5

В текущем исходном файле паттерн `до свидания` записан как:

```js
/^до\s*свидания/
```

без `$` в конце.

Поэтому сейчас правило сработает не только на чистое:

```text
До свидания
```

но и на сообщение, начинающееся с этой фразы.

Например:

```text
До свидания, но у меня ещё один вопрос
```

тоже может быть пропущено.

Для строгой логики чистого прощания паттерн должен иметь вид:

```js
/^до\s*свидания$/
```

---

## 10. Чистые благодарности

Пропускаются сообщения, состоящие только из благодарности.

Например:

```text
Спасибо
Спасибо вам
Спасибо большое
Спасибо огромное
Спасибо вам большое
Большое спасибо
Огромное спасибо
Огромнейшее спасибо
Благодарю
Благодарю вас
```

При этом:

```text
Спасибо, а как закрыть карту?
```

не считается чистой благодарностью и остаётся для разметки.

Диагностическая причина:

```text
thanks
```

---

# Технические ошибки

## 11. Стандартная техническая ошибка бота

Ответ бота дополнительно проверяется на стандартный текст:

```text
Возникла техническая ошибка. Пожалуйста, для продолжения консультации
обратитесь на горячую линию банка по номеру 8-800-250-57-57.
```

Проверка выполняется именно по тексту ответа, потому что техническая ошибка может произойти внутри любого сценария и Class/State не обязательно будут `AnyError`.

Если найден этот текст, сообщение пропускается.

Диагностическая причина:

```text
technicalError
```

---

# Запрос оператора

## 12. Чистая просьба соединить с человеком

Скрипт распознаёт сообщения, смысл которых целиком сводится к просьбе соединить клиента с человеком.

Поддерживаются различные формы слов:

```text
оператор
специалист
сотрудник
консультант
менеджер
человек
живой человек
```

Также распознаются конструкции вроде:

```text
Оператор
Специалист
Живой человек

Мне нужен оператор
Нужен специалист

Позовите оператора
Дайте специалиста
Подключите сотрудника

Соедините меня с оператором
Свяжите меня со специалистом

Переведите меня на оператора
Переключите на специалиста

Как связаться с оператором
Поговорить с человеком

Связь с оператором
Соединение с оператором
```

Слово `пожалуйста` и обычная пунктуация при этой проверке удаляются.

Например:

```text
Пожалуйста, соедините меня с оператором.
```

может быть распознано как чистый запрос человека.

Диагностическая причина:

```text
pureOperatorRequest
```

### Защита от ложных пропусков

Regex привязан к началу и концу сообщения.

Поэтому наличие слова «оператор» или «специалист» внутри полноценного банковского вопроса само по себе не является причиной пропуска.

Например:

```text
Оператор списал деньги с карты
```

или:

```text
Мне специалист сказал, что платёж не прошёл
```

должны остаться для проверки.

Важно: фактический код `isPureOperatorRequest` не требует Class = `Clarity`. Проверка выполняется по тексту клиента, если сообщение дошло до этого этапа алгоритма.

# DontHaveQuestions

## 13. Завершение диалога без дополнительных вопросов

Класс `/DontHaveQuestions` не пропускается целиком.

Для пропуска должны одновременно выполняться два условия:

```text
Class строго равен /DontHaveQuestions
```

и сообщение клиента соответствует безопасному короткому шаблону.

Например:

```text
Нет
Нет, спасибо
Нет спасибо
Нет спасибо большое
Нет, не нужно, спасибо
Всё
Все
Всё, спасибо
Вопросов нет
Вопросов больше нет
Больше вопросов нет
Нет больше вопросов
Спасибо, вопросов больше нет
```

Такой подход нужен, чтобы случайно не пропустить содержательный ответ клиента, который по ошибке оказался в `/DontHaveQuestions`.

Диагностическая причина:

```text
noMoreQuestions
```

---

# Что происходит с сообщением после проверки

Если ни одно правило пропуска не сработало:

1. внутри сообщения ищется кнопка **«Верно»**;
2. кнопка автоматически нажимается;
3. сообщение визуально подсвечивается.

Используется:

```text
оранжевая линия слева
светло-оранжевый фон
```

и добавляется подпись:

```text
● Размечено автоматически — проверьте
```

Это позволяет быстро глазами найти все сообщения, которые были размечены автоматически.

# Диагностика

При запуске в консоль браузера выводится:

```text
verno-marking-bookmarklet v8.5 запущен
```

Для каждого сообщения также выводятся:

```text
cls
state
clientText
willSkip
skipReason
```

Текущие значения `skipReason`:

```text
clarityTransferToOperatorPair
classOrState
buttonClick
greeting
goodbye
thanks
technicalError
pureOperatorRequest
noMoreQuestions
```

Если сообщение нужно размечать:

```text
skipReason: null
```

После анализа выводится общий итог:

```text
Итого: размечено X, пропущено Y
```

и после завершения:

```text
Готово.
```

# Приоритет проверки сообщения

Упрощённо порядок принятия решения выглядит так:

```text
Сообщение
   ↓
NoMatch?
   ├─ Да -> РАЗМЕТИТЬ
   ↓
TransferToOperator?
   ├─ Да + Clarity/TransferToOperator -> ПРОПУСТИТЬ
   └─ Да + любая другая комбинация -> РАЗМЕТИТЬ
   ↓
Безопасный Class / State / пара?
   └─ Да -> ПРОПУСТИТЬ
   ↓
Нажатие quick reply?
   └─ Да -> ПРОПУСТИТЬ
   ↓
Чистое приветствие?
   └─ Да -> ПРОПУСТИТЬ
   ↓
Чистое прощание?
   └─ Да -> ПРОПУСТИТЬ
   ↓
Чистая благодарность?
   └─ Да -> ПРОПУСТИТЬ
   ↓
Стандартная техническая ошибка?
   └─ Да -> ПРОПУСТИТЬ
   ↓
Чистый запрос оператора?
   └─ Да -> ПРОПУСТИТЬ
   ↓
DontHaveQuestions + безопасная фраза?
   └─ Да -> ПРОПУСТИТЬ
   ↓
РАЗМЕТИТЬ "ВЕРНО"
```

# Изменение правил

При развитии бота правила следует расширять в соответствующих местах:

```text
Новые безопасные классы
-> SKIP_CLASSES

Новые безопасные State
-> SKIP_STATES

Новые безопасные пары Class + State
-> SKIP_CLASS_STATE_PAIRS

Новые приветствия
-> GREETING_PATTERNS

Новые прощания
-> GOODBYE_PATTERNS

Новые благодарности
-> THANKS_PATTERNS

Новые варианты запроса человека
-> HUMAN_ROLE / OPERATOR_PATTERNS

Новые варианты "вопросов больше нет"
-> NO_MORE_QUESTIONS_PATTERNS

Изменение подсветки
-> HIGHLIGHT_STYLE
```

# Установка bookmarklet

Для использования скрипта в браузере необходимо создать закладку и вставить в поле URL минифицированную версию, начинающуюся с:

```text
javascript:
```

Для установки используется файл:

```text
verno-marking-bookmarklet-v8.5.min.js
```

После обновления версии рекомендуется открыть консоль браузера и проверить строку:

```text
verno-marking-bookmarklet v8.5 запущен
```

Если отображается другая версия или строка отсутствует, в URL закладки, скорее всего, остался старый код.
